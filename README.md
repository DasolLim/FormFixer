[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

A real-time AI fitness coaching platform. GymFXR runs pose estimation directly in the browser to analyze exercise form as you train — live rep counts, joint-angle feedback, and a per-set form score, with no wearable, native app, or server round-trip in the hot path.

**Live:** [gymfixer.vercel.app](https://gymfixer.vercel.app)

## Highlights

- **Real-time, client-side computer vision** — 33-point pose estimation at up to 30fps entirely in the browser via MediaPipe Tasks Vision, with no video ever sent to a server
- **21 hand-built exercise-scoring engines** — squat, push-up, pull-up, Nordic curl, and others, each combining joint-angle geometry, bilateral symmetry checks, and tempo analysis into a live form score
- **Signal-processing pipeline for noisy pose data** — hysteresis + exponential-moving-average smoothing drives rep-phase detection so a single jittery frame can't miscount a rep
- **Multi-orientation auto-calibration** — a stability gate that detects camera angle (front/side) and body position (standing, prone, hanging, seated, kneeling) before scoring begins
- **LLM-generated content with schema-validated output** — workout programs are generated by an LLM (via OpenRouter) and parsed through a strict Zod schema before ever reaching the database, so malformed model output fails closed instead of corrupting data
- **CI-gated fullstack app** deployed on Vercel with GitHub Actions running lint + build on every push

## Core Features

### Real-time form coaching
Point a webcam at yourself, pick from 21 supported exercises, and get live feedback: rep count, joint angles, a 0–100 form score, and spoken cues (Web Speech API) as you train. A calibration step confirms you're fully in frame and correctly oriented before a session starts.

### Guided & AI-generated workout programs
Browse structured multi-week programs, or describe your goals and have one generated by an LLM — validated against a strict schema, then scheduled onto a calendar.

### Nutrition tracking
Log meals by type and search USDA FoodData Central for accurate macro data, proxied through a server-side API route.

### Progress tracking
Weight trend chart, progress photos, and a training journal, alongside personal records and workout-frequency analytics.

### Social & gamification
Friends, gym invites, an in-app notification center, XP with levels, and streaks — built to make consistency visible and social.

### Installable PWA
A service worker precaches the app shell and versions its runtime cache, so the app installs to a home screen and stays usable offline.

## Technical Architecture

### Pose estimation & form-scoring pipeline

```
Webcam frame
  → MediaPipe Tasks Vision          (33-landmark pose estimation, in-browser, WASM)
  → Landmark normalization           (src/features/pose)
  → Confidence gating                 per-landmark visibility check — reject unreliable frames
  → Calibration gate                  multi-frame stability + orientation/position auto-detect
  → Per-exercise scoring engine        (1 of 21, src/features/form-engine/engines)
      ├─ Angle rules      (joint-angle geometry)
      ├─ Symmetry rules   (bilateral left/right comparison)
      └─ Tempo rules      (rep pacing)
  → Rep-counter state machine         hysteresis + EMA-smoothed phase transitions
  → Feedback prioritizer              severity-ranked cues with per-cue cooldown
  → Voice + on-screen feedback        (Web Speech API)
```

Everything above the network boundary runs client-side — the camera feed never leaves the browser. Each exercise engine is an isolated module implementing a shared interface (`src/features/form-engine/form-engine.ts`), so adding an exercise means writing new geometry rules against the existing pipeline, not touching the pipeline itself.

### AI-assisted program generation

User goals are sent to an LLM through OpenRouter; the response is parsed as JSON and validated against a nested Zod schema (`GeneratedProgramSchema`) covering program metadata, per-day structure, and per-exercise set/rep/rest bounds. Output that fails validation is rejected before it ever reaches the database — the LLM is treated as an untrusted input source, not a trusted writer.

### Application layer

- **Next.js 14 App Router** with a mix of Server Components (data-fetching pages) and Client Components (interactive UI), plus dedicated API routes for AI generation and third-party proxying
- **Supabase** for Postgres, authentication, and session cookies (via `@supabase/ssr`)
- **Middleware-enforced route protection** — session presence is checked server-side in `src/middleware.ts` before any protected page renders, redirecting unauthenticated requests before they hit the route
- **Per-query authorization** — every data-access function touching private data explicitly scopes its query to the authenticated `user_id` (the only exception is the program catalog, which is deliberately public)
- **Zustand** for lightweight global UI state (XP/level), **Zod** for all external-input and LLM-output validation, **Recharts** for analytics visualizations, **Three.js** for a 3D muscle-engagement avatar

### CI/CD

GitHub Actions runs `npm ci` → `lint` → `build` on every push and pull request, independent of the deploy pipeline — a build or lint failure surfaces immediately as a check, rather than silently reaching production. Vercel's Git integration handles actual deployment: every push to `main` builds and deploys automatically.

## Getting Started

### Prerequisites

- Node.js 18+
- A [Supabase](https://supabase.com) project (Postgres + Auth enabled)
- A [USDA FoodData Central](https://fdc.nal.usda.gov/api-key-signup.html) API key
- An [OpenRouter](https://openrouter.ai) API key

### Setup

```bash
git clone https://github.com/DasolLim/FormFixer.git
cd FormFixer
npm install
```

Create a `.env` file in the project root:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
USDA_API_KEY=your-usda-fooddata-central-key
OPENROUTER_API_KEY=your-openrouter-key
OPENROUTER_MODEL=anthropic/claude-3-5-sonnet
```

Provision your Supabase project with the schema this app expects — see `src/lib/database.types.ts` and the query functions under `src/lib/*/sessions.ts` for the tables each feature reads and writes.

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

### Other scripts

```bash
npm run build       # production build
npm run start        # serve the production build
npm run lint         # lint
npm run lint:fix     # lint, auto-fixing
```
